# Project Report: DeepScan 
**AI-Generated Text & Source Code Forensic Detector**

## 1. Executive Summary
DeepScan is a full-stack, machine-learning-powered forensic tool designed to distinguish between human-authored and AI-generated content. Unlike wrapper applications that rely on expensive, opaque third-party APIs (like OpenAI or GPTZero), DeepScan calculates token probabilities, linguistic perplexity, and structural burstiness locally. It provides an interactive, visual heatmap that explains its verdict sentence-by-sentence, supporting both natural language (essays, articles) and source code (Python, Java, etc.).

## 2. Core Features
*   **Dual-Mode Engine:** Processes both prose (natural language) and source code (evaluating AST depth and variable naming entropy).
*   **Sentence-Level Visual Heatmap:** Uses the Monaco Editor to highlight text dynamically (Green = Likely Human, Red/Orange = Likely AI).
*   **Deep Statistical Dashboard:** Displays key metrics including Mean Perplexity, Minimum Perplexity, Burstiness Index (Fano factor), and Top-$K$ token distributions.
*   **Forensic Export:** Generates verifiable PDF/JSON reports for academic integrity audits or code reviews.

## 3. System Architecture & Tech Stack
The architecture is designed to be lightweight, scalable, and entirely hostable on free-tier infrastructure.

*   **Frontend (User Interface):** 
    *   *Stack:* React.js (Vite), Tailwind CSS, `@monaco-editor/react`.
    *   *Role:* Handles user input, visualizes the color-coded heatmap, and displays metric charts.
*   **Backend (Inference API):**
    *   *Stack:* Python 3.11, FastAPI, Uvicorn.
    *   *Role:* Tokenizes incoming text, parses code syntax, and orchestrates the machine learning pipeline asynchronously.
*   **Machine Learning Runtime:**
    *   *Stack:* `onnxruntime`, `transformers` (Hugging Face), `scikit-learn` or `xgboost`.
    *   *Role:* Executes a CPU-optimized, quantized language model to calculate text perplexity in milliseconds.
*   **Database (Optional):**
    *   *Stack:* PostgreSQL (via Supabase or Neon).
    *   *Role:* Stores hashed analysis logs and user history.

## 4. How the ML Pipeline Works
When a user submits text, the backend executes the following pipeline:

1.  **Segmentation:** The text is split into discrete sentences using natural language processing (e.g., `spaCy` or regex). For code, an Abstract Syntax Tree (AST) is generated.
2.  **Perplexity ($PPL$) Calculation:** A base language model predicts the likelihood of each word given the preceding words. AI models output predictable sequences, resulting in *low* perplexity.
    $$ \text{PPL}(X) = \exp \left( -\frac{1}{N} \sum_{i=1}^{N} \log P(x_i \mid x_{<i}) \right) $$
3.  **Burstiness Calculation:** Evaluates the variance of sentence structures. Humans write in irregular bursts (high variance), while AI maintains a uniform tempo (low variance).
    $$ \text{Burstiness} = \frac{\sigma_{\text{PPL}}}{\mu_{\text{PPL}}} $$
4.  **Classification:** The extracted features (Mean PPL, Burstiness, Length, Entropy) are fed into a trained classifier (XGBoost) which outputs the final $P(\text{AI})$ confidence score.

## 5. Dataset Requirements & Training Strategy
To answer the crucial question: **Yes, you need datasets, but you do not need to train a massive Large Language Model from scratch.** 

The ML system relies on two separate models. Here is the data strategy for each:

### Part A: The Base Language Model (No Training Required)
To calculate token probabilities (Perplexity), you will **not** train a model. You will download a pre-trained, open-source model like `GPT-2-small` (124M parameters) or `DistilGPT-2`. You simply convert this model to ONNX format to run fast on a CPU.

### Part B: The Final Classifier (Training Required)
To convert the raw math (Perplexity, Burstiness) into a final percentage (e.g., "98% AI Generated"), you **must train a lightweight classifier** (Logistic Regression or XGBoost). You will need a labeled dataset containing both human-written and AI-generated samples.

**Recommended Datasets for Natural Language (Prose):**
1.  **HC3 (Human ChatGPT Comparison Corpus):** Available on Hugging Face (`Hello-SimpleAI/HC3`). Contains tens of thousands of questions answered by both human experts and ChatGPT.
2.  **DAIGT V2 (Detect AI Generated Text):** Created for a Kaggle competition, containing human student essays mixed with essays generated by various LLMs.

**Recommended Datasets for Source Code:**
1.  **Human Code:** Use the **CodeSearchNet** dataset (available on Hugging Face), which contains high-quality, human-written functions from GitHub across multiple languages.
2.  **AI Code (Synthetic Generation):** You will likely need to generate the "AI side" of this dataset yourself. You can write a short Python script that takes prompts from the *CodeSearchNet* dataset and passes them to a free API (like Groq/Llama-3 or Gemini) to generate AI equivalent code. 

**Training Process:**
1. Pass your dataset (5,000 human texts + 5,000 AI texts) through your Perplexity engine.
2. Extract the features into a CSV (`label, mean_ppl, burstiness, variance`).
3. Train an `XGBoost` classifier on this CSV. The resulting `.pkl` or `.json` model file will be tiny (under 1 MB) and will be used by your FastAPI backend.

## 6. Implementation Roadmap
*   **Phase 1 (ML Core):** Download `distilgpt2`, write the Python script to calculate sentence perplexity, and test it locally on a few paragraphs.
*   **Phase 2 (Data & Training):** Download the HC3 dataset, run your Phase 1 script over it to generate features, and train the XGBoost classifier.
*   **Phase 3 (Backend):** Wrap the ML pipeline in FastAPI endpoints (`/analyze_text` and `/analyze_code`).
*   **Phase 4 (Frontend):** Build the React app, integrate the Monaco Editor, and map the sentence scores to the background color heatmap.
*   **Phase 5 (Deployment):** Deploy frontend to Vercel and backend to Render/Hugging Face Spaces.
